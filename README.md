WorkBuddy 客户端「Buddy 加油站」积分体系的定时自动领取项目：**每日签到 + 断签补登 + 连登奖励兑换 + 盲盒抽奖**，全部通过客户端自有通道完成，不读取登录令牌、不修改客户端文件、可随时卸载。

> [!IMPORTANT]
> **运行前提（先读这段）**：本项目的定时任务跑在 **WorkBuddy 客户端的自动化**里。任务定义（`tasks/buddy-daily-tasks.json`）也可以挂载到其他支持定时调度的 agent 上，但有两个硬前提，缺一不可：
>
> 1. **承载任务的 agent 必须处于激活状态**（在线且能响应调度）——任务挂了上去而 agent 没激活，等于没挂；
> 2. **WorkBuddy 客户端必须处于激活状态**（在跑、已登录）——签到走 WBIPC 通道，要求宿主就是 WorkBuddy 客户端；成长中心走 CDP 通道，要求客户端在跑且 9222 调试端口已开。
>
> 挂到非 WorkBuddy 的 agent 上时，WBIPC 签到那步会不可用（报 `E_NOT_WORKBUDDY`），此时可用成长中心脚本自带的兜底签到（走 CDP、幂等）顶替。

## ✨ 功能

| # | 功能 | 说明 |
|---|---|---|
| 1 | 每日签到 | 走 WBIPC 端上通道领取当日积分；已签则空转（幂等） |
| 2 | 断签自动补 | 读当月日历找断点，用补登卡补签；每轮最多 1 张，无卡/无断点/数据异常一律跳过，绝不瞎补 |
| 3 | 连登奖励兑换 | 7d / 14d / 28d 三档，只领已解锁且未领的档位（奖励含积分/能量/补登卡/抽奖机会） |
| 4 | 盲盒抽补签卡 | 有机会才抽，每轮最多 1 次；中实物奖只在日志提醒填地址，不代填 |

设计原则：

- **幂等**：任何一步重复执行无害，已签/已领状态下只会多几次查询；
- **保守写**：所有写操作前先查状态，条件不满足就跳过；字段缺失不猜，接口改版时不对着空气 POST；
- **早起 + 全天补救窗口**：定时任务定在 07:30，签到早早落袋；万一失败，当天还有充足时间手动补；
- **零凭据**：两条通道都不碰令牌——WBIPC 的鉴权由客户端宿主注入，CDP 通道借的是页面自身已登录的会话。

## ⏰ 定时任务（每天 07:30 一轮）

`tasks/buddy-daily-tasks.json` 是一份完整的任务定义：先 WBIPC 签到，再跑成长中心（补登/兑换/盲盒），最后一并汇报。两种装法任选：

**方式 A · 交给 WorkBuddy 自动创建**（推荐）

在 WorkBuddy 对话里把 JSON 内容发给它，让它按定义创建定时任务。或者用这句懒人 prompt：

```text
帮我把这个仓库配置成每天 07:30 自动运行：<把仓库地址贴在这里>
步骤：clone 到本地 → 按 tasks/buddy-daily-tasks.json 的定义创建定时任务
（名称 / rrule / prompt 照抄 JSON，cwd 指向仓库根目录，python 换成本机实际命令）
→ 手动跑一次 python scripts/growth_auto.py --now --once 验证链路。
```

**方式 B · 手动创建**

在客户端「自动化」里新建每日 07:30 的任务，prompt 用 JSON 里的原文，cwd 指到仓库根目录。

> [!TIP]
> **为什么是 07:30**：签到早早落袋，白天电脑出任何状况都不影响已领积分；万一失败，早上就看到报告，当天有充足时间手动补。写操作全部幂等，重复执行不会重复到账；手动补跑时盲盒会按剩余机会再抽一次（每轮一次的上限），介意的就别补跑那一步。

> [!NOTE]
> 自动化平台目前**一个任务只能挂一个时间点**，所以早晚双保险需要建两个任务（复制 JSON，改 rrule 即可）。

## 🔧 手动运行（先验证再定时）

```bash
python scripts/checkin_wbipc.py            # 签到（已签会显示 skip）
python scripts/growth_auto.py --now --once # 成长中心一轮，stdout 出摘要
```

实际输出长这样（示例，来自 2026-10-27 实测的“全跳过”安全态）：

```text
成长中心一轮完成 → 签到：已签（连登 8）；补登：无补登卡；
兑换：无可兑档位（7d:claimed 14d:locked 28d:locked）；盲盒：无抽奖机会
```

完整日志在 `scripts/growth.log`，每轮一行摘要，不含账号信息。

## ⚙️ 工作原理

```
WorkBuddy 定时任务（每天 07:30）
   │
   ├─ 第一步 ─► scripts/checkin_wbipc.py
   │             WBIPC 端上通道（宿主注入鉴权）
   │             POST /v2/billing/meter/daily-checkin
   │
   └─ 第二步 ─► scripts/growth_auto.py --now --once
                 CDP 注入（127.0.0.1:9222）→ 页面内 window.wb.http
                 签到(幂等) → 补登 → 兑换 → 盲盒，串行执行、逐项汇报
```

调试端口两种开法（任选一，都是客户端自己支持的正规通道，不用改包体）：

1. **启动参数**：`WorkBuddy.exe --remote-debugging-port=9222`
2. **环境变量**（推荐）：`WORKBUDDY_REMOTE_DEBUGGING_PORT=9222`——客户端读到后自行 `appendSwitch` 开端口，并把 WebSocket 来源限制在 localhost 白名单；设好后正常点图标启动也生效。改完环境变量需重启资源管理器（或重启电脑）才对图标点击生效。

> [!IMPORTANT]
> 端口只绑 `127.0.0.1`，且来源白名单由客户端自己限制，与传参方式安全性相同。CDP 注入是**运行时行为**，客户端重启即消失，不留任何文件级改动。

## 🧪 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| WBIPC 报 `E_NOT_WORKBUDDY` | WBIPC 通道由客户端宿主注入，在客户端外手动跑没有这座桥 | 正常现象。定时任务跑在 WorkBuddy 内不受影响；手动验证请直接跑 `checkin_wbipc.py`，报同样的错即确认仅宿主内可用 |
| 连不上 `127.0.0.1:9222` | 客户端没开调试端口 | 用上面两种开法之一；设了环境变量的话，确认改过之后重启过资源管理器 |
| growth 接口全 404 | 用 POST 打了查询路由 | 查询类必须 GET、写类必须 POST；本脚本已按此分工，自己写代码时注意（详见 `docs/api-contract.md`） |
| 有代理时误报“端口没开” | Python 的 urllib 尊重 `HTTP_PROXY`，连 127.0.0.1 都走代理 | `cdp_client.py` 已强制直连（`ProxyHandler({})`），不受环境影响 |
| 「兑换：14d locked」 | 连登天数不够，服务端未解锁 | 正常，脚本只领已解锁档位、不催熟；解锁那轮自动领 |
| 「补登：无补登卡」 | 补登卡余额为 0 | 正常；补登卡来自连登奖励和盲盒 |
| 「盲盒：无抽奖机会」 | 机会余额为 0 | 正常 |
| 签到显示“今日已领” | 当天已签过 | 幂等正常，不会重复发积分 |
| 定时任务到点没跑 | 平台调度有确定性抖动（分钟级） | 等几分钟；还不行就手动跑 `growth_auto.py --now --once` 补，幂等无害 |
| 定时任务根本没触发 | 客户端没在跑，或模型服务当时不可用 | 自动化由客户端调度并执行，两边有一边不在线，当天就不跑；补跑即可 |
| 「页面无响应」整轮失败 | 网络抖动，CDP 一帧 45 秒没等全 | 脚本会自动重试一次；仍失败就当天手动补跑 |
| 客户端升级后脚本失效 | 接口/字段可能变了 | 对照 `docs/api-contract.md` 重新实测（文档附了复验方法） |

<details>
<summary><strong>常见问题（FAQ）</strong></summary>

**为什么不自动派 Buddy 旅行、领任务奖励？**
设计取舍：本项专注「连签不断 + 该领的全领」，旅行派发和任务体系收益零碎还要每天盯着名额，性价比低，故不收录。相关接口在 `docs/api-contract.md` 有记录，想扩展可自行添加。

**一天跑一次够吗？**
对签到够用：07:30 开跑 + 全天补救窗口。想要更强保险就再建一个傍晚任务（复制 JSON 改 rrule），幂等设计下重复跑无害。

**能挂到其他 agent 上吗？**
能，任务定义是通用的 prompt，任何支持定时调度的 agent 都能挂。但记住开头「运行前提」的两条：承载 agent 要激活、WorkBuddy 客户端也要激活。换到非 WorkBuddy 的 agent 时，签到那步改用成长中心脚本自带的兜底签到（`growth_auto.py` 第一步，走 CDP 幂等），别用 WBIPC 那条。

**支持 macOS / Linux 吗？**
**本项目是 Windows 专属的**，在 macOS / Linux 上不能直接跑，需自行移植。三处硬依赖（均为代码事实，非推测）：

1. `checkin_wbipc.py` 靠 `LOCALAPPDATA` / `ProgramFiles` 环境变量和 `C:`~`F:` 盘符扫描定位客户端内置库目录——非 Windows 上这些全部落空，脚本直接以退出码 2 报「未找到 WorkBuddy 内置库目录」；
2. `growth_auto.py` 的单实例锁用 `tasklist /FI` 探活（Windows 专属命令）——非 Windows 上该命令不存在，锁会**静默失效**（永远认为旧进程已死），并发保护形同虚设；
3. CDP 通道本身是跨平台的（WebSocket + 页面内 `window.wb.http`），macOS 客户端据其启动参数也支持 `--remote-debugging-port`——**但这一条未实测，仅为文档推断**；且 WBIPC 是 Windows 端上通道，换平台后签到只能走成长中心脚本的 CDP 兜底。

**脚本会动我的账号数据吗？**
只调四个官方接口（签到/补登/兑换/抽奖），全是界面按钮能做的操作；不读令牌、不改文件、不碰会话数据。

</details>

## 🔐 安全与隐私

- 不读取、不打印、不落盘任何登录令牌；两条通道分别靠宿主注入和页面自身会话；
- 不修改 WorkBuddy 客户端任何文件（无 app.asar 改动、无 DLL、无注入残留——CDP 注入是运行时行为，客户端重启即消失）；
- 日志（`scripts/growth.log`）与状态文件（`scripts/growth_state.json`）只记录结果摘要，不含账号信息；已列入 `.gitignore`；
- 仓库不含任何密钥，可安全 fork 与分享——它只作用于**运行者自己本机**的登录态。

> [!WARNING]
> **CDP 端口的暴露面（如实说明）**：调试端口开着时，**本机任何进程**都能连上它并通过 CDP 执行任意 JS——这不只限于本项目，所有走 `--remote-debugging-port` 的工具（Codex++、WorkDaddy 等）都面临同样的面。缓解措施：端口只绑 `127.0.0.1`、WebSocket 来源被客户端限制在 localhost 白名单；建议**用完 growth 脚本就关掉端口**（或仅在信任的机器上常开），本机别有来路不明的程序。

## ⚠️ 已知限制

- **依赖承载方在线**：自动化模式由 WorkBuddy 客户端调度并执行，模型服务不可用或客户端没在跑，当天任务就不跑——挂载/部署时务必确认承载 agent 处于激活状态（见开头「运行前提」）；
- **关机/睡眠错过即错过**：07:30 电脑没开机，当天不会自动补跑（平台无“错过后补跑”机制），醒来后手动跑一次 `growth_auto.py --now --once` 即可补（幂等）；
- 接口契约基于 WorkBuddy 5.9.2（2026-10-27），客户端升级后若字段/路由变化需重新实测（`docs/api-contract.md` 有完整记录和复验方法可对照）；
- 成长中心依赖调试端口；客户端没开端口时脚本会跳过并如实报告，不影响签到；
- 连登兑换三档的解锁进度由服务端决定，脚本只领“已解锁未领”，不催熟；
- 盲盒是写路径不可逆操作，脚本保守处理（有机会才抽、每轮一次）。

本项目**不收集、不上传、不存储**任何用户数据：脚本只在本机与本地客户端通信（`127.0.0.1` / 本机 IPC 通道），无远程服务器、无埋点、无遥测。运行产生的 `growth.log`、`growth_state.json` 仅留在本机项目目录内，已被 `.gitignore` 排除，不会进入版本库。
